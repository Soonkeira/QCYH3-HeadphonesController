# 尚需真实场景验证的事项（1.0.0 交付后人工验收清单）

> 范围：以下事项**无法在本机自动化或脚本化走查中闭环**（需要耳朵听、跨设备配合、肉眼目视或
> 改变系统/网络环境），按任务要求逐条给出测试步骤与预期。
> 已由脚本化终验覆盖的部分不再列入（九页 UI 走查、EQ 本地往返、按键编辑器只读、托盘菜单、
> 通知送达证据链等，见 §10 执行记录与 `docs/upgrade/verification/` 截图与 dump）。
> 完成一项请在该项前打勾并注明日期。

---

## ① 通知横幅屏上目视

**背景**：送达证据链已闭环——应用日志 4 次记录触发（如 `[17:07:55] 低电量提醒：当前电量 50%（阈值 100%）`），
Windows `Microsoft-Windows-PushNotification-Platform/Operational` 事件日志同秒记录
「已将具有通知跟踪 ID 4385 的 Toast 传送到会话 1 上的 NotifyIconGeneratedAumid_…」（Id 3052/3153）。
但全屏截图多次未捕捉到**屏幕右上角横幅**（本机可能在系统设置中开启了「勿扰/专注助手」，
或横幅已进入通知中心而不弹横幅）。

**测试步骤**：
1. 确认系统「设置 → 系统 → 通知」总开关开启、「勿扰」（专注助手）关闭；
2. 把 `%APPDATA%\QcyH3Controller\config.json` 的 `LowBatteryThresholdPercent` 临时改为 `100`（或设置页无法改到 100 时直接改文件）；
3. 重启应用（等待耳机连接成功，电量 ≤100 必然触发）；
4. 观察屏幕右下角是否弹出「QCY H3 电量低 / 当前电量 50%，请及时放入充电」横幅；点击横幅应打开快捷面板；
5. 点击任务栏时钟打开通知中心，确认该通知已归档；
6. 把阈值改回 `20`。

**预期**：横幅在屏上目视可见、点击行为正确、通知中心有归档；若勿扰模式下不弹横幅但通知中心有归档，属 Windows 正常行为，记录即可。

## ② 查找耳机 / 播放提示音 首次触发效果

**背景**：真机 ack 通道已验证（status=0），但 R2 级外放音效的实际效果（是否响铃/提示音内容/音量）从未触发过。
UI 按钮带确认弹窗，协议依据见 feature-matrix §8（0x4B / 0x3D）。

**测试步骤**：
1. 控制中心 → 功能页 → 「查找耳机」→ 确认弹窗 → 确认；耳机应以外放铃声定位（over-ear 大音量，**先摘下耳机**）；
   验证后确认响铃如何停止（再次点击 / 铃声自动停止）；
2. 「播放提示音」→ 确认 → 耳机应外放一段提示音，确认音量适中、无破音；
3. 各触发一次即可，记录效果；若无任何声音，回撤按钮并用 CLI `probe-tone` 复核 ack。

**预期**：查找耳机 = 响铃定位；播放提示音 = 外放提示音；两者均不改变降噪/EQ/按键等任何设置。**无效则回撤按钮并回探针复核**（feature-matrix 解锁条件）。

## ③ 四档降噪 + 三场景 + 抗风的耳朵听感确认

**背景**：13 模式读/写与回读确认均为真机协议验证，但「降噪强度是否符合档位语义」只有耳朵能裁决。

**测试步骤**（佩戴耳机，在典型噪声环境逐档切换）：
1. 快捷面板或控制中心降噪页：关闭 → 通透 → 降噪低 → 降噪中 → 降噪高，确认听感单调递进（通透=能听清环境音，降噪档位=低频噪声递减）；
2. 自适应档：确认启用后随环境变化自动调节；
3. 通勤低/中/高、室内低/中/高：确认与纯降噪档位听感有可辨差异（通勤偏低频轰鸣、室内偏人声中频）；
4. 抗风噪：户外或风扇前切换，确认风噪明显受抑；确认抗风噪无档位语义（UI 三个档位均不亮）为正确表现。

**预期**：13 档听感单调且分组语义与 UI 文案一致；写后回读确认（UI 选中态与耳机实际状态一致）。

## ④ 自动关机实际定时行为

**背景**：0x14 读→写→回读已探针验证（功能页选择即写、回读确认、乐观快照），但「耳机真的会在设定时长无操作后关机」未实际观察过。
**注意：会真关机**——观察结束后记得重新设置或改回「不自动关机」。

**测试步骤**：
1. 控制中心 → 功能页 → 自动关机 → 选「5 分钟」；
2. 停止任何音频播放，把耳机放置不动（不入盒、不触碰按键）；
3. 等待约 5 分钟：耳机应自动关机（指示灯熄灭/断连，应用状态转「重连中/耳机不可达」）；
4. 重新开机，确认应用自动重连、功能页自动关机档位显示「5 分钟」；
5. 验证完成后按需改回「不自动关机」（0xFFFF）。

**预期**：到时自动关机、回读一致、断连后应用状态文案正确（重连中 → 耳机不可达 → 重开后自动恢复）。

## ⑤ DPI 100% / 150% / 200% 切换显示

**背景**：本机 125% 已全量走查（快捷面板、控制中心六页、EQ 编辑器、按键编辑器截图与 UIA 度量均无裁切）。
其余档位因需注销/重启资源管理器且改变系统环境，未在终验中切换。

**测试步骤**：
1. 设置 → 系统 → 屏幕 → 缩放，依次切换 100% → 150% → 200%（每档注销或重启应用）；
2. 每档检查：快捷面板全部 chip 文字完整（「重低音」「自定义」「抗风」）、控制中心六页布局、EQ/按键编辑器、托盘图标清晰度；
3. 截图留档，改回 125%。

**预期**：全部文字完整无裁切、布局无重叠溢出、托盘图标清晰（多分辨率 ICO 16–256 七帧）。

## ⑥ 多显示器混合 DPI

**背景**：本机双显示器（扩展桌面）已验证应用正常打开，但未逐台切换主屏/拖动跨屏观察 DPI 重算。

**测试步骤**：
1. 两台不同缩放比的显示器（如 100% + 150%）；
2. 把快捷面板/控制中心拖到另一台显示器上，观察窗口是否按目标屏 DPI 正确重排（文字不糊不裁）；
3. 把主显示器设为另一台，再走一遍快捷面板与控制中心；
4. 恢复原主屏设置。

**预期**：跨屏拖动后按目标 DPI 正确渲染；WPF PerMonitorV2 清单已启用（`app.manifest`）。

## ⑦ 蓝牙关 → 开自动恢复

**背景**：`BluetoothOff` 一等状态 + `Radio.StateChanged` 监听恢复（D4 修复）有单元测试与状态机矩阵覆盖，
真机恢复路径仅在开发期提示过「蓝牙不可用」文案，未做过完整关→开→自动回连的定时验收。

**测试步骤**：
1. 连接成功后，从系统设置/托盘关闭 Windows 蓝牙；
2. 确认应用状态文案变为「蓝牙不可用」（快捷面板/控制中心/托盘 tooltip）；
3. 等待 ≥30 秒（确认不会凭空乱试）后重新打开蓝牙；
4. 秒表计时：从蓝牙开启到耳机重新连接成功（状态「已连接」）的时长。

**预期**：状态正确进入「蓝牙不可用」；开蓝牙后 30 秒内自动恢复连接、数据全部刷新（无需手动点「立即重连」）。

## ⑧ 休眠唤醒重连

**背景**：睡眠/唤醒是真实使用的高频路径（下班合盖、早上开盖），未纳入脚本化验收。

**测试步骤**：
1. 连接成功后让系统睡眠（开始菜单 → 睡眠）；
2. 唤醒系统，秒表计时到应用重新显示「已连接」；
3. 期间确认无报错（`%LOCALAPPDATA%\QcyH3Tray\error.log` 无新增异常）、EQ/降噪等控制 immediately 可用。

**预期**：唤醒后 30–60 秒内自动回连；无异常日志；若耳机在睡眠期间被手机抢占，转 ⑨ 流程。

## ⑨ 耳机被手机抢占后回连

**背景**：单控制连接限制（手机 QCY App 抢占 = 握手无响应超时）为真机已知行为，应用表现（状态文案 + 持续重连 + 手机断开后回连）未做专项验收。

**测试步骤**：
1. 应用已连接耳机；用手机 QCY App（或手机蓝牙设置）主动连接该耳机；
2. 观察应用状态：应出现连接失败/耳机不可达类文案并持续重连（不是假死在「已连接」）；
3. 手机断开耳机连接（或耳机关机再开机）；
4. 秒表计时到应用自动回连成功。

**预期**：抢占期间状态诚实（不显示假的已连接）、重连循环存活；手机释放后自动回连（受断开冷却 2s / AccessDenied 冷却 5s 影响属预期，见 plan §8 偏差 4）。

## ⑩ 托盘右键菜单（真人操作复核）

**背景**：终验已用合成鼠标事件验证菜单弹出与五项齐全（打开控制面板/打开控制中心/立即重连/开机自启/退出，
见 `verification/15-tray-menu.*`），但合成点击与真人点击在 Win11 溢出飞出层中的路径可能存在差异，顺手复核即可。

**测试步骤**：真人右键托盘图标（含溢出区内的图标）→ 确认菜单弹出位置合理、五项齐全、「开机自启」勾选态正确。

**预期**：与 15-tray-menu.png 记录一致。
